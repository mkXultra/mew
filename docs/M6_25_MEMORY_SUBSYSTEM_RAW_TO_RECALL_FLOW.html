M6.25 メモリサブシステムの流れ

このページは、設計書から「raw data から MemoryCard へ変換する流れ」と 「RecallRequest から検索結果へ返す流れ」だけを抜き出した説明です。 実装者が各段階で何を読み、何を書き、何を検証し、何を次へ渡すかを確認できるように整理しています。

1. raw data → memory 変換 2. recall → retrieval 検索
Phase B: Typed card / seed retrieval Phase C: 評価ハーネス契約 Phase D: graph 展開 / 最適化 index Phase E: context packet 投影

1. raw data → MemoryCard 変換フロー

raw transcript、tool log、verifier output、reviewer comment、diff は、そのまま durable memory にはなりません。 まず証拠として provenance に保存され、抽出・型付け・検証・承認を通過したものだけが committed MemoryCard になります。

通常パス ingest_experience は provenance と candidate/proposal を作るだけです。 committed card へ進むには、proposal、approval、commit の監査可能な状態遷移が必要です。
特権的 eval seed パス seed_eval は Phase C の fixture setup 専用です。 gold label、trap family、期待回答、hidden scorer view を入れてはいけません。 seed された card は audit 上は識別可能ですが、ranking は seed_eval metadata を読んではいけません。

1. raw 入力を受け取る

読む transcript、tool log、command output、verifier output、reviewer comment、diff、file hash。
書く まだ durable memory は書かない。入力単位を capture 対象として整形する。
検証 raw transcript を summary/details へ直接コピーしない。大きな payload は audit に入れない。
出す provenance capture 用の source record。
↓

2. provenance event を捕捉する

読む source run/turn、fixture experience id、actor/producer、payload hash、短い excerpt。
書く provenance_events。必要なら source_experience_id を保存する。
検証 redaction policy、excerpt サイズ、producer enum、privacy boundary。
出す ProvenanceReceipt と provenance event id。後続の evidence link が参照する。
↓

3. candidate を抽出する

読む provenance event、raw excerpt、既存 card、extractor rule。
書く MemoryCandidate。この時点では recall 対象ではない。
検証 raw を丸写ししない。summary は短く、details は合成された説明にする。
出す 候補 claim、候補 evidence link、初期 confidence。
↓

4. type と facet を割り当てる

読む candidate、scope、applicability、authority、invalidator、lifecycle hint。
書く kind、scope、applicability、evidence role、invalidator baseline、projection mode。
検証 semantic fact、procedure、failure shield、policy/preference、task episode のどれかへ過度に広げず型付けする。
出す proposal 可能な typed candidate。
↓

5. deduplication と contradiction/staleness/invalidator check

読む 既存 committed/superseded card、current evidence、card scope、applicability ref。
書く merge/split decision、contradiction state、staleness state、drop/downgrade reason。
検証 異なる scope の claim を混ぜない。stored baseline と現在の file/symbol/command/verifier/task/authority evidence を比較する。
出す proposal、rejected candidate、または supersede/tombstone が必要な mutation intent。
↓

6. approval gate を通過する

読む proposal、evidence links、authority source、actor、operation type。
書く approval audit event。通常は candidate → proposal → approved → committed。
検証 policy/preference は user/reviewer/maintainer authority が必要。debug/manual でも通常は proposal/approved を記録する。
出す approved proposal、または terminal rejected。
↓

7. commit、supersede、tombstone を実行する

読む approved proposal、target card、mutation op、schema version、authority。
書く memory_cards の committed revision。必要なら旧 card を superseded/tombstoned にする。
検証 rejected/tombstoned/superseded から committed へ戻さない。restore は新 revision を作る。
出す commit result、card id、revision lineage、result hash。
↓

8. graph、index、audit を更新する

読む committed card、graph refs、graph-derived material、index mode、request hash。
書く graph refs がある場合だけ graph_nodes/graph_edges。Phase B では simple lexical/direct scan index。audit は常に書く。
検証 graph endpoint は canonical node に解決できなければ reject。graph refs がない Phase B commit は graph 書き込み no-op。
出す retrieval 可能な committed card、derived index refresh、audit event。
状態遷移 意味 通常の制約
candidate → proposal → approved → committed 通常の durable memory 化。 各段階を audit に残し、authority と evidence role を保存する。
candidate/proposal/approved → rejected 不採用。 terminal。後から committed へ戻さない。
committed → superseded/tombstoned 新 revision、または監査履歴として非 active 化。 通常 recall から外す。rollback 目的でも履歴は消さない。
forget privacy/security/user-driven removal。 payload、support id、caller-visible provenance を redaction cascade で露出しない。
Phase C の eval setup では、公開 fixture operation と prefix hash に含まれる seed_eval 入力だけが seed できます。 実行後に作られる receipt、audit id、provenance id、card id は入力 hash には含めず、artifact に保存します。

2. RecallRequest → memory retrieval フロー

recall は、committed MemoryCard を単に全文検索する処理ではありません。 現在の repo/verifier/task/authority evidence を使って古い記憶を落とし、privacy と scope を先に守り、 ranking と audit 可能な RetrieveResult を返します。Phase E の context packet 投影は、この検索結果とは別段階です。

1. RecallRequest を組み立てる

読む query、caller、authorization scope、memory scope、intent tags、limits。
書く request id/hash。intent tag は retrieval/ranking/audit 用で、planner action ではない。
検証 scope と privacy を later filter へ渡せる形に正規化する。
出す retrieval plan の入力。
↓

2. current evidence snapshot を添付する

読む repo/branch/commit、file state、symbol state、command state、verifier result、task contract、authority event。
書く recall request 内の current_evidence。これは durable memory ではない。
検証 observed_at、hash、state、target scope、provenance ref が invalidator と比較可能か。
出す freshness、staleness、contradiction 判定の現在値。
↓

3. seed retrieval を実行する Phase B

読む committed card、scope/kind/lifecycle/state/authority filter、query text。
書く candidate result set。Phase B では direct scan または同期 rebuild された simple lexical/BM25-like index。
検証 approval_state は committed。tombstoned/deleted/forgotten は通常 retrieval に入れない。
出す graph 展開前の seed cards。
↓

4. 必要なら graph expansion を行う Phase D

読む seed card の graph refs、canonical graph_nodes、graph_edges。
書く expansion frontier と usage count。derived graph index は rebuild 可能で非 authoritative。
検証 max depth、fanout、node/card/char/latency budget。redacted evidence の edge は展開しない。
出す 追加候補 card と graph proximity signal。
↓

5. governance filtering を固定順で適用する

読む card privacy、caller authorization、scope_key、applicability、staleness、contradiction、invalidator。
書く dropped record、dropped_count_by_reason、内部 audit。caller-visible ID は許可されたものだけ。
検証 sharing=team/shared でも allowed_scope_ids を bypass しない。fresh evidence は古い memory を override できる。
出す ranking へ渡せる governance-passed cards。
↓

6. deterministic ranking と CanonicalScore を作る

読む structured match、lexical score、scope modifier、authority/freshness/proximity、projection cost。
書く score_components と score/final_score。artifact では CanonicalScore 文字列。
検証 NaN/Infinity を reject。Decimal + ROUND_HALF_UP で小数 4 桁、例 0.1250。
出す rank 付き evidence。tie-break も deterministic。
↓

7. RetrieveResult と usage を返す

読む ranked cards、active current_support links、authorized provenance、drop reasons、usage counters。
書く result hash、ranked_evidence、abstained reason、dropped_count_by_reason、usage artifact。
検証 support_experience_ids は current_support role だけ。proof/reviewer/lineage refs は metadata の role map へ分ける。
出す adapter/scoring が読める検索結果。Phase E の prompt 投影とは区別する。
順序 gate 見るもの 落とす例
1 privacy/sharing PrivacyRules.sharing、allowed_scope_ids、redaction state。 privacy_block、forgotten、redacted。
2 caller authorization scope caller が許可された canonical scope key。 out_of_scope、unauthorized scope。
3 memory scope match task、branch、repo、project、user、team/shared の containment。 別 repo の project fact、別 task の task-only memory。
4 applicability match applies_to、does_not_apply_to、prerequisite、counterexample。 missing_evidence、counterexample match。
5 staleness / contradiction invalidator baseline と current evidence の hash/value/observed_at。 stale、contradicted、invalidator_triggered。

ranking の tie-break

優先順 条件
1高い final_score。
2広い scope より exact scope match。
3高い authority strength。
4新しい last_verified_at。
5短い summary / 低い projection cost。
6辞書順で小さい card_id。

RetrieveResult の主要フィールド

フィールド 意味
ranked_evidencerank、card id、score、score_components、scope、state、metadata。
support_experience_idsactive current_support から得た公開 support id の集合。P1 scoring は集合として扱う。
provenance_refscaller に見せてよい current_support refs だけ。その他 role は metadata に分ける。
dropped_count_by_reasondrop reason 別の件数。非公開 card の存在を漏らさない。
usagelatency、cards scanned/ranked/returned/dropped、graph 展開数、projection chars、index mode。
Phase E では MemoryContextBuilder が retrieve result から model-visible context packet を作ります。 検索 artifact、audit log、full provenance payload はそのまま prompt に入れません。
